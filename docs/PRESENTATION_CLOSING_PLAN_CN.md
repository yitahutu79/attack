# 当前汇报收尾主线与讲法

更新时间：2026-04-24

这份文档对应当前版本的 `presentation.html` 和 `paper/main.tex`。  
它不是旧版“明天汇报草稿”，而是当前论文阶段最适合的收尾讲法，重点是：讲清楚主胜利点、跨域验证、压力测试和局限，不把结果说过头。

## 1. 当前最稳的一句话主线

> 本文提出 `Attentive TCN-WGAN-GP`，做的是低误报、窗口级、可解释的网络入侵检测；在 `CICIDS2017` 上取得主结果，在 `SWaT` 上完成强验证，在 `UNSW-NB15` 上展示压力测试行为，在 `TON_IoT` 上明确给出域外局限。

## 2. 汇报时建议的叙事顺序

### 第一步：问题

讲法：

> 很多入侵检测方法把每条 flow 当成独立样本，但真实攻击常常表现为一段时间内的模式变化；同时，安全运维很在意误报率，所以只报 AUC 不够。

### 第二步：方法

讲法：

> 我们把 flow 序列切成窗口，用 TCN 建模时间依赖，用 attention pooling 聚合关键时间步，用 WGAN-GP 稳定对抗训练，再把 critic 证据和 feature deviation 证据融合成最终异常分数。

### 第三步：实验协议

讲法：

> 我们固定 `W=128`、`stride=16`、`anomaly_ratio=0.15`，重点在 target-FPR 工作点下比较不同方法，而不是只看离线排序分数。

### 第四步：主结果

讲法：

> 在 CICIDS2017 上，模型在严格低误报工作点取得最高 F1 和极低的实际 benign test FPR；当放宽误报预算时，recall 接近 0.97，同时保持最高 F1。

### 第五步：跨数据集

讲法：

> SWaT 说明方法能迁移到工控场景；UNSW 说明阈值跨域迁移并不容易；TON_IoT 则清楚地展示了当前方法的域外边界。

### 第六步：解释性与落地性

讲法：

> 模型不只是输出一个异常分数，还能给出 attention、Integrated Gradients、SHAP 等多视角证据，帮助分析员审计为什么报。

## 3. 当前最推荐的收尾页内容

收尾页建议只保留四点：

1. `窗口级 + 低误报` 是本文最核心的定位。
2. `CICIDS2017` 和 `SWaT` 支撑主要正向结论。
3. `UNSW-NB15` 和 `TON_IoT` 说明阈值迁移与跨域泛化仍有难点。
4. `XAI` 让告警结果更可审计，而不是更黑盒。

## 4. 当前最稳的结论句

可以直接讲：

> 这篇工作的价值不在于把所有数据集都做成第一，而在于把低误报窗口级告警、阈值校准和可解释审计三件事放到同一个入侵检测框架里，并把强项、压力点和局限都讲清楚。

## 5. 当前最容易被问到的问题

### 为什么要用窗口，而不是单条 flow？

因为很多攻击需要看相邻 flow 的时间关系，窗口级告警也更接近真实监控系统的响应单位。

### 为什么同时报 `target FPR` 和 `observed test FPR`？

因为阈值是在 benign calibration data 上定的，但测试集 benign 分布可能漂移。只报 target FPR 会把这个问题藏起来。

### 为什么 SWaT/UNSW 表里没有 RF/MLP？

因为 formal one-class split 下训练集主要是 benign，监督分类器没有公平训练条件。

### 为什么表里保留 `W` 列？

因为 `ALoRa` 当前主文结果还是 `W=20`，其他大多是 `W=128`。保留 `W` 列是为了诚实说明输入长度差异。

## 6. 当前不建议在收尾时讲的话

不建议：

- “我们的方法在所有数据集上都最好”
- “attention 单独就带来了性能提升”
- “XAI 提升了模型效果”
- “已经证明可以无条件跨域泛化”

建议替换成：

- “本文方法在目标低误报场景下表现最强”
- “attention 与 WGAN-GP 的组合在当前工作点最有效”
- “XAI 提供告警审计证据”
- “跨域阈值迁移仍是开放问题”

## 7. 一句话总结

当前最好的收尾方式不是继续堆数字，而是把论文的真实贡献边界讲稳：`CICIDS` 主胜利、`SWaT` 强验证、`UNSW` 压力测试、`TON_IoT` 局限，再加上低误报和可解释这两个落地价值点。
