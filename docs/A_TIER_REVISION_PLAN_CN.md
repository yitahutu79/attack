这份文档不再作为“未来某天要补什么”的旧计划稿，而是改成当前版说明：论文为了达到更强投稿标准，哪些补强已经完成，哪些仍然值得继续做，哪些应该明确写成局限而不是继续硬补。

## 1. 当前判断

如果按今天的完成度看，这篇论文已经不是“只有方法、没有证据”的阶段，而是已经具备完整论文形态：

- 主数据集 `CICIDS2017` 的低误报主结论已经成型。
- `SWaT` 已经提供了可信的第二数据集强验证。
- `UNSW-NB15` 已作为压力测试进入主文。
- `TON_IoT` 已被明确定位为域外挑战与局限，而不是强行包装成优势结果。
- 现代 baseline 已补齐到足以支撑当前主张的程度。
- XAI、消融、参数敏感性、多 seed 和轻量效率分析都已经有正文落点。

所以，当前论文距离更强投稿标准的主要差距，已经不是“有没有实验”，而是“口径是否统一、叙事是否稳、剩余风险是否处理干净”。

## 2. 四个顶刊补强项的当前状态

### 2.1 多数据集泛化

这部分的旧缺口已经不再成立。

当前状态：

| 方向 | 当前情况 | 论文角色 |
|---|---|---|
| `CICIDS2017` | 已完成 | 主战场 |
| `SWaT` | 已完成 | 跨域强验证 |
| `UNSW-NB15` | 已完成 | 压力测试 |
| `TON_IoT` | 已完成但结果不强 | limitation / cross-domain challenge |

当前最重要的写法不是继续把数据集数量堆更多，而是把角色写清：

- `CICIDS2017` 负责证明核心低误报结论。
- `SWaT` 负责证明结论不只在一个网络数据集上成立。
- `UNSW-NB15` 负责展示阈值迁移和数据分布变化下的压力。
- `TON_IoT` 负责诚实呈现 domain shift 局限。

仍然可选但不必强追的增强项：

- `CSE-CIC-IDS2018`
- 更系统的跨数据集阈值迁移实验

如果当前目标是把论文收干净而不是开启新一轮大扩张，那么多数据集这一项已经达到“可投且有说服力”的水平。

### 2.2 近年 SOTA baseline

这部分也已经从“缺口”转成“统一口径问题”。

当前已覆盖：

- 传统方法：`IsolationForest`、`OneClassSVM`
- 监督窗口模型：`RF`、`MLP`
- 深度序列模型：`LSTM-AE`、`LSTM-AD`
- 现代异常检测：`GANomaly`、`DeepSVDD`、`TranAD`
- 新近时序模型：`ALoRa`、`Anomaly Transformer`、`TimesNet`、`DLinear`、`Autoformer`

当前真正剩下的问题：

1. `ALoRa` 仍有 `W=20` 与 `W=128` 口径未完全统一的问题。
2. 不同表之间需要把 `target FPR`、窗口长度和 split 说明写得更一致。
3. 主文中不需要再继续无上限加 baseline，否则会稀释主线。

结论：

- baseline 数量已经足够。
- 现在更重要的是保证公平性解释和表格口径一致。

### 2.3 可解释性

这部分已经不再停留在“只有 attention 图”。

当前已具备：

- attention 权重分析
- Integrated Gradients
- SHAP
- 时间维度与特征维度的解释图

这意味着论文已经可以支撑下面这条更稳的主张：

> 模型不仅输出异常分数，还能给出多视角的报警证据，用于辅助分析师审计告警。

当前还需要注意的不是“再补一个解释算法”，而是写作边界：

- 不把 attention 直接等同于 faithful explanation。
- 强调 attention 是内部证据聚合机制。
- 把 IG/SHAP 作为对最终异常分数的补充审计视角。

如果之后还有余力，最值得补的是更强的 case study 组织，而不是再堆新的解释方法。

### 2.4 效率与鲁棒性

这部分是四项里最接近“已做轻量版、但还不算很满”的一项。

当前已有：

- CPU-only 推理吞吐
- 模型大小
- 轻量实时性分析
- Gaussian noise sanity check

当前仍属弱项的部分：

- 缺失值扰动
- threshold drift 的系统实验
- 更完整的 latency / p95 / memory 统计

这里的建议不是现在立刻大扩实验，而是分两层处理：

- 当前投稿：保留已有效率结果，鲁棒性谨慎表述为轻量 sanity check。
- 后续 revision：再考虑缺失特征、漂移和更完整部署指标。

## 3. 现在最值得继续同步的内容

如果目标是把这套文档系统彻底变成“当前可用说明”，接下来真正该做的是统一叙事，而不是继续制造新计划。

优先级最高的同步点：

1. 所有文档都统一承认论文现在是“四数据集分工式叙事”，不是“所有数据集全面领先”。
2. 所有文档都统一说明 baseline 已经补齐，剩余问题是 `ALoRa@W128` 和窗口口径。
3. 所有文档都统一把 `TON_IoT` 写成 limitation，不再写成待补主结果。
4. 所有文档都统一把“继续冲更多实验”改成“先清理现有主表和口径”。

## 4. 还剩下的真实 A 类风险

下面这些风险是今天仍然真实存在的，比再加一两个实验更重要：

### 4.1 表格口径混合

需要统一说明：

- 哪些表用 `target FPR = 0.05`
- 哪些表用 `target FPR = 0.15`
- 哪些数据集采用 formal one-class split
- 哪些 baseline 因训练条件不同而不进入某些主表

### 4.2 `ALoRa` 窗口长度

只要 `ALoRa` 还没有稳定回填到 `W=128`，主文和汇报中就要保留清楚说明，不能假装完全同口径。

### 4.3 贡献边界

论文最稳的主张仍应是：

> 在窗口级网络异常检测里，`Attentive TCN-WGAN-GP` 在低误报约束下提供了更实用的告警质量，并具备可审计解释。

不建议把主张膨胀成“全面超过所有模型、所有场景都最优”。

### 4.4 统计显著性

目前可以强调多 seed 的稳定趋势，但不适合写成“对全部 baseline 有统计显著优势”。

## 5. 当前版行动建议

如果接下来只做最值钱的事，建议顺序如下：

1. 清理并确认 `ALoRa@W128` 的最终状态，再决定是否统一移除表格中的 `W` 列。
2. 统一 `paper/main.tex`、`presentation.html`、结果记录文档中的 `target FPR` 和 split 说明。
3. 把所有文档中的旧式计划语气改成当前状态语气，避免误导成“这些实验还没做”。
4. 最后再做英文润色、版式和补充材料收尾。

## 6. 一句话结论

这份“CCF A 补强计划”到今天已经不再是待办清单，而更像一份完成度评估：多数据集、现代 baseline、XAI 和基础效率分析都已基本补齐；当前最需要做的是统一口径、处理 `ALoRa` 残留问题，并把论文主张稳稳收束在“低误报、可解释、可落地”这条线上。
